Why the hell now another kind of solution? But what if we want to interchange forms or form models between different systems in different languages? What if we want to use the same forms in complete different usecases like CMS, Apps or PWAs or Paperware? What if we want to process the form results in a direct, data-driven way and what, never the less, we want to render a form within Plone as easy as before? Then edi.jsonforms could be another kind of solutions for Webforms in Plone with some useful sidekicks. Lars Walther will show the fundamental concepts of edi.jsonforms while Julian Pollinger will show some technical details of implementation and roadmap.
